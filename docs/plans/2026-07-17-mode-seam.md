# Mode Seam Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development in-session) to implement this plan task-by-task.

**Goal:** Put every modal mode (Search, Rename, CreateItem, DirConsole, Zoxide) behind one interface — `ModalInput` — so the `Mode` enum collapses to `Normal | Modal(Box<dyn ModalInput>)`, mode logic gains locality (one file per mode), and each mode becomes testable as a pure state machine.

**Architecture (decisions settled in grilling, do not re-litigate):**
1. **Pure ops** — adapters never touch panels/fs/redraw: `handle_key(KeyEvent) -> ModeOp`; the manager applies every op in one `apply_mode_op` method and derives redraws there.
2. **One trait** — `ModalInput: Draw` subsumes the `Console` trait; `ConsoleOp` is deleted at the end.
3. **Esc forwarded** — each adapter returns its own cancel op; the blanket Esc cleanup in `handle_event` (manager.rs:1265-1277) is deleted in the final task. Esc in Normal mode (parser.clear + unmark_all) stays central.
4. **Adapters draw themselves** — `ModalInput: Draw` plus `region() -> ModalRegion { ConsoleOverlay, FooterLine }`; the manager assigns screen regions.
5. **Incremental** — Search → Rename → CreateItem → consoles → collapse. Every task compiles, passes `cargo test`, is e2e-verified over the debug socket (see CLAUDE.md), and is one commit. Old and new dispatch coexist until Task 6.

**Tech Stack:** Rust, crossterm KeyEvent, existing `Draw` trait (src/panel/mod.rs:63), existing `Input` widget (src/panel/input.rs), debug socket for e2e (CLAUDE.md).

**Vocabulary:** use CONTEXT.md terms — modal mode, mode operation (ModeOp), modal region.

**Porting rule:** the behavior of each mode is ported *verbatim* from the current inline arms — this refactor moves code, it does not change what keys do. Before each task, read the current arm carefully; after each task, the e2e check must show identical behavior. When the plan's code sketch and the current arm disagree, the current arm wins (note the deviation in the commit message).

**Debug-socket compatibility:** `state_snapshot()`/`mode_name()` (manager.rs) must keep reporting the same mode strings ("search", "rename", "mkdir", "touch", "console", "normal") — CLAUDE.md documents them and e2e checks assert them. This is why `ModalInput` has a `name()` method.

**Step 1: Create the module**

```rust
//! The modal-mode seam: every modal mode implements [`ModalInput`] —
//! keys in, [`ModeOp`]s out, self-drawn in its assigned [`ModalRegion`].
//! Adapters are pure state machines: they never touch panels, the
//! filesystem, or redraw flags. The PanelManager applies ops centrally.

use anyhow::Result;
use crossterm::event::KeyEvent;
use std::path::PathBuf;

use super::Draw;

/// The effect a modal mode requests from the application.
///
/// Ops that conclude the mode (FinishSearch, Rename, Create, Exit) make
/// the manager return to Normal after applying them.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ModeOp {
    /// Nothing to apply
    None,
    /// Change the visible directory (consoles navigate live)
    Cd(PathBuf),
    /// Live-update the center panel's search highlight
    UpdateSearch(String),
    /// Conclude the search with the final pattern and leave the mode
    FinishSearch(String),
    /// Live-preview the rename target name
    RenamePreview(String),
    /// Perform the rename and leave the mode
    Rename { to: String },
    /// Live-preview the element being created (footer shows it)
    CreatePreview { name: String, is_dir: bool },
    /// Create the element and leave the mode
    Create { name: String, is_dir: bool },
    /// Leave the mode without a concluding action; cleanup says what to undo
    Exit { cleanup: Cleanup },
}

/// What the manager must undo when a modal mode is cancelled.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Cleanup {
    None,
    /// Clear the search highlight
    Search,
    /// Clear the rename preview
    RenamePreview,
    /// Clear the new-element preview
    CreatePreview,
    /// Navigate back (consoles cancel to their starting directory)
    CdTo(PathBuf),
}

/// Screen area a modal mode is granted for drawing.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ModalRegion {
    /// Centered overlay (consoles)
    ConsoleOverlay,
    /// Single input line in the footer (search/rename/create)
    FooterLine,
}

/// The interface every modal mode implements.
pub trait ModalInput: Draw + Send + Sync {
    /// Handle one key event, returning the op the manager should apply.
    /// Esc arrives here like any other key — cancel semantics belong to
    /// the mode, not the manager.
    fn handle_key(&mut self, key_event: KeyEvent) -> ModeOp;

    /// Where this modal wants to render.
    fn region(&self) -> ModalRegion;

    /// Mode string for the debug socket / state snapshot
    /// ("search" | "rename" | "mkdir" | "touch" | "console").
    fn name(&self) -> &'static str;
}
```

4. `apply_mode_op`: one method applying every op and deriving redraws:
   ```rust
   fn apply_mode_op(&mut self, op: ModeOp) {
       match op {
           ModeOp::None => {}
           ModeOp::Cd(path) => { self.jump(path); }
           ModeOp::UpdateSearch(pattern) => {
               self.center.panel_mut().update_search(pattern);
               self.redraw_center();
           }
           ModeOp::FinishSearch(pattern) => {
               // port the current Enter-in-Search behavior verbatim
               self.center.panel_mut().finish_search(&pattern);
               self.mode = Mode::Normal;
               self.redraw_panels();
               self.redraw_footer();
           }
           ModeOp::Exit { cleanup } => {
               self.apply_cleanup(cleanup);
               self.mode = Mode::Normal;
               self.redraw_panels();
               self.redraw_footer();
           }
           // Rename/Create ops arrive in Tasks 3-4 — use todo!() arms
           // guarded by unreachable modes until then, or implement now
           // by porting; prefer porting only what's exercised.
           _ => unreachable!("op not yet wired: introduced by a later task"),
       }
   }

   fn apply_cleanup(&mut self, cleanup: Cleanup) {
       match cleanup {
           Cleanup::None => {}
           Cleanup::Search => self.center.panel_mut().clear_search(),
           Cleanup::RenamePreview => self.center.panel_mut().clear_rename_preview(),
           Cleanup::CreatePreview => self.center.panel_mut().clear_new_element(),
           Cleanup::CdTo(path) => self.jump(path),
       }
   }
   ```

## Risks / open ends (watch during execution)

- **Input widget coupling:** `Input::update` takes `(KeyCode, KeyModifiers)` — if a mode arm today filters modifiers before calling it, port that filter into the adapter, not into the trait.
- **`finish_search` semantics:** check whether Enter-in-search also moves the selection (`select_next_marked`-style); the e2e assertion in Task 2 must match actual behavior.
- **Blanket-Esc double duty until Task 6:** during Tasks 2-5 the blanket handler must not fire for `Mode::Modal` (guard added in Task 2, Step 4.3) — a missed guard shows up as "Esc exits mode but also unmarks everything".
- **Redraw parity:** apply_mode_op centralizes redraw decisions for modal modes; compare against each deleted arm's redraw calls one-by-one (this is candidate 2's future seam — don't optimize here, just preserve).

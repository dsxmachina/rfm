## Confirmed bugs

### BUG-1 — Search live-highlight overlay misaligned, corrupts visible filename
- **Step:** 05.2 — **Severity:** visual — **Class:** render (socket/`entries`
  correct, screen corrupted)
- **Reproduced twice.** During live search the bold-red highlight overlay is
  drawn one cell too far right, so the visible filename is corrupted
  (`report-2.txt` renders as `rreport2.txt`, `report.txt` as `rreporttxt`).
  Root cause: the overlay hard-codes the name-start column at `x = +4`
  assuming a 2-cell file icon, but tmux renders the icon glyph as 1 cell, so
  the real name starts at column 3. `state`, `entries`, marks and committed
  search are all correct — purely the live-highlight render path.
- **Report:** [runs/run1/05-console-search-and-input-modes.md](run1/05-console-search-and-input-modes.md)
  (BUG-run1-01)
- **Disposition: FIXED** in `d668c3d` — the highlight is now drawn *inline*
  (part of the sequential name print) instead of an absolute-positioned
  overlay, so it flows with the same cursor advancement as the rest of the row
  and cannot land on the wrong cell regardless of icon width. Regression test:
  `styled_entry_tests::search_highlight_preserves_visible_characters`.
  Re-verified in run 2.

### BUG-2 — FIFO preview pane stuck on "Loading..." forever
- **Step:** 07.17 — **Severity:** visual — **Class:** render (screen shows a
  stuck placeholder; state and screen agree on the wrong thing)
- **Reproduced twice.** Selecting a FIFO leaves the preview pane on a
  `Loading...` + path placeholder indefinitely. The preview column is driven
  as a directory panel whose `loading` flag is set and never cleared for a
  non-regular file (the async load never completes / falls through to
  `PreviewPanel::Empty`). No wedge — `state` stays responsive, `seq` stable;
  the footer perms (`prw-`) and mime (`text/plain`) are correct.
- **Report:** [runs/run1/07-opener-and-mime.md](run1/07-opener-and-mime.md)
  (BUG-run1-01)
- **Disposition: FIXED** in `56aa473`. Root cause: the async `PreviewManager`
  treated every non-directory as a regular file and called `FilePreview::new`,
  which for a FIFO reaches the text arm and *reads the pipe* — blocking the
  worker thread forever, so the `Loading...` placeholder was never replaced.
  The worker now classifies via `classify_preview` (mirroring
  `PreviewPanel::from_path`): a non-regular, non-dir path resolves to
  `PreviewPanel::Empty` and is never opened. Regression test:
  `content::tests::classify_preview_maps_fifo_to_empty_not_file`.
  Re-verified in run 2.

### BUG-3 — Preview column stale after leaving a deleted cwd (`h`)
- **Step:** 12.8 — **Severity:** papercut — **Class:** both (`preview_path`
  wrong AND screen stale; they agree with each other but both lag the real
  selection)
- **NOT reproduced twice** — the deleted-dir precondition is consumed by the
  step and self-heals on the next cursor move. After `rm -rf` of an entered
  dir then `h` to the parent, `preview_path` stays at the deleted dir and the
  right column shows its stale content; any `j`/`k` bounce fixes it. Does not
  fail the step's core robustness contract (no wedge, listing coherent).
- **Report:** [runs/run1/12-complex-and-stress.md](run1/12-complex-and-stress.md)
  (BUG-run1-01)
- **Disposition: FIXED** in `6f3218a`. On investigation it *was* fully
  deterministic — the run-1 executor's fixture merely allowed a cursor move
  that masked it (self-heal). Root cause: `move_left` performs a Miller shift
  that reuses the come-from directory as the preview; correct only while the
  restored selection still points at it. When that dir was deleted underneath
  us, the parent panel reloaded and the cursor fell onto a sibling, but the
  preview kept showing the stale dir. `move_left` now re-drives the preview
  (gated on preview visibility; `new_panel_delayed` short-circuits on an
  unchanged path, so the common case is a no-op). Regression test:
  `manager::tests::move_left_refreshes_preview_when_selection_moved_off_the_come_from_dir`.
  Re-verified in run 2.

## Protocol feedback — actioned

The single largest source of false-FAIL risk and executor rework was the
shared-`/tmp` fixture parent (its watcher churn floods the 200-line log ring
and defeats every idle-`seq`, log-line and thumbnail-count assertion) and a
shared scratchpad `env.sh` that parallel executors clobbered. Both, plus
seven smaller friction points, are fixed for the next run. Changes applied in
this pass:

**Cross-cutting (README.md + affected sections):**
1. **Quiet fixture parent.** Harness now creates the fixture under a fresh
   empty parent (`PARENT=$(mktemp -d); FIXTURE="$PARENT/fx"; mkdir "$FIXTURE"`)
   so the left/parent panel watches a quiet dir, not churning `/tmp`. Sections
   relying on idle-seq stability (01, 12), log lines (03, 06, 08, 10, 11) or
   thumbnail counts (09) reference it.
2. **Parallel-safe harness.** README now mandates `tmux kill-session` + `rm -f
   $SOCK` *before* `new-session`, and per-section env filenames (`env-secNN.sh`)
   — never a shared `env.sh`.
3. **Launch the binary directly** as the tmux session command (`tmux
   new-session -d … "env … ./target/debug/rfm …"`), not via `send-keys` into an
   interactive login shell (Atuin/zsh history-search intercepted the typed
   command).
4. **`send-keys -l` for literal tokens** that collide with tmux key names
   (`delete`, `space`, `up`, `tab`, …). Technique note added; section 11 fixed
   (11.8/11.11).
5. **Reverse-video detection** matches `[7m` **OR** `[0;7m` (rfm emits both);
   use `capture-pane -e`. Section 01 guidance updated.
6. **Log assertions primary via socket, wide window** (`log 200` queried
   immediately after the action; on-screen widget sampled 2–3× before asserting
   absence). Applied to 03/06/08/10/11/12.
7. **Portable timing** (`date +%s%N`, or just the `timeout 12` wedge-guard);
   all README socket reads wrapped in `timeout 12`. Section 07.17 fixed.
8. **Empty-panel sentinels** documented (`preview_path == "path-of-empty-panel"`,
   root `left_path` not a real path) — README pitfalls + section 02.
9. **SELECT navigation helper** — compute the target's visible index from
   `entries center` and step the shortest direction, never blind `j`. Sections
   04 and 08 updated.

**Section-specific wording fixes** (to prevent false-FAILs): 02.13/02.17/02.19,
04.2/04.10, 05.7/05.10/05.11, 08.11/08.15/08.17, 09.1/09.6/09.12 — details in
the individual section files' change history and the per-section run reports.
